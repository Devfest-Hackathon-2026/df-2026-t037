関数1：onLogCreated（Firestoreトリガー）

  1. EXP＝分数×(1＋weights[category]÷100)×連続ボーナス（3日×1.05・7日×1.10・14日×1.15・30日×1.20）。その日の合計が学年の目安の1/4を超えたらstreak＋1（例：物理20分×1.4×1.05＝29）
  2. users.exp に加算し、last7も更新（トランザクション）
  3. exp≧plan.firstでstage2、≧plan.finalでstage3（最終進化）。上がった瞬間にevolvedAtを書き、画面で進化演出
  4. bond＝floor((exp−plan.final)÷((plan.bond10−plan.final)÷10))（最大10）。3・5・7・10でunlockedに装備・かっこいい姿を追加
  5. 上限なし：教科ごと累計3000分で★、累計50000EXPごとにメダル、月に標準ペースの半分で季節装備。親密度10のあとは2000EXPごとにおみやげ

関数2：getLaunchSuggestion（アプリ起動時に呼ぶ）

  1. suggestions/今日 があれば、それを返して終わり（Geminiを呼ぶのは1日1回まで）
  2. 不足カテゴリ＝weights−last7比率 が最大のもの。分数＝(last7合計÷7)×不足分、5分単位に切上げ
  3. その教科のEXP倍率（1＋配点比率）と、最終進化までの残りEXP÷直近7日の1日平均EXP＝「あと何日」も計算
  4. この数字と昨日の記録をGeminiに渡し、JSON（text 1〜2文）で受け取る。数字はプロンプトに埋めて、Geminiには計算させない

セキュリティルール

  • logsは本人のuidだけ作成可。minutesは5〜600の整数、categoryは5種のどれか
  • usersのexp・stage・bond・unlockedは関数だけが書ける（ズルで進化できない）。equippedとcoolFormは本人が変えられるが、timerStartedAtがあるあいだ（勉強タイマー中）は変更不可
  • facultiesは全員読み取りのみ

モンスターの描き方

  • line[stage]の体のSVGに、装備のSVGを重ねる。かっこいい姿は縁の色と光の粒を足すだけ
  • 歯車の歯数・アンテナの長さ・絵の具の大きさは、usersの数値からその場で計算
  • 動きはCSSアニメーション（ふわふわ・まばたき＋学部ごとの1つ）。歯車や翼の速さは今日の学習分数をCSS変数で渡して変える

作る順番

  1. Firebaseプロジェクト作成、Hosting＋Authでログインまで。初期設定と毎年4月1日（進級）に、学年の目安（高1 2.5h・高2 3.5h、高3は毎日8h、高1・2の長期休み×1.5）でシーズンの10%（最长30日）・45%・85%までの時間を出し、×60×avgMult×facultyFactor×1.15×paceでplanを保存。3月31日にキャラをdexへ移す。毎朝の定期実行で、前日未記録ならおやすみ券かstreak半分
  2. facultiesの11件を投入、記録画面からlogsを書く
  3. onLogCreatedで集計と進化（ここまでで動くデモになる）
  4. getLaunchSuggestionとGemini。模試の成績表の写真をGeminiで読み取るverifyExam（判定・偏差値・順位だけ保存し、写真は削除）、最後に見た目の調整

関数のサービスアカウントにだけVertex AIの利用権限（Vertex AI User）を付け、ブラウザにAPIキーは置かない。チャット履歴を3か月で消す要件は、Firestoreの有効期限（TTL）ポリシーでexpireAtを設定すれば自動削除できる。
